# Skill 场景评估

`cases.json` 包含正向、边界、组合和不应触发的场景。它是回归材料，**不是本版本已经跑出的模型评测成绩**。

## 如何运行真实行为评估

1. 给候选 agent 提供任务 prompt、skill 可见描述，以及任务需要的原始代码/曲线/论文等证据。不要给候选看 expected_skills、checks 或 hard_failures。
2. 路由评估先只给可发现的名称/描述，观察选择；再允许读取选中的 skill。评估执行质量时补齐最小可运行项目或数据，不能仅靠一句 prompt 宣称代码行为正确。
3. 在隔离工作区运行，限定资源与允许的副作用。远程任务或计算费用测试按具体授权执行。
4. 原样保存输出、文件与执行记录。记录模型、时间、工具、输入版本、skill 版本、预算及缺失条件。
5. 独立评审查看场景要求、skill 和原始证据，按下面标准给出证据；无独立评审时明确是自审。

## 看结果，不数关键词

分别检查路由、技术正确性、范围/授权、可执行性和不确定性。按案例要求记录 pass / partial / fail / not-run，引用实际输出或产物。不能因为出现 M1、hparam 或 warmup 等词就判通过。

任何 hard failure 都单独报告，不能用其他分数抵消。尤其关注：默认 SAI 被误设为可选、第二套参数 schema、无效试验作为反证、test 选参、固定 loss 阈值、破坏必要 warmup，以及未授权执行。

更新 skill 后优先重跑受影响场景。真实 GPU 效果或计算节省需要预算、基线、重复与原始 trial 记录，不能从文字评审推断。

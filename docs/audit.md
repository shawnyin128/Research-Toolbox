# 三个 Skill 的梳理与优化

审查范围：两个 GitHub 仓库的 skill、references、模板、README 与评估说明，以及用户提供的 fork-test 压缩包。所有文档内容作为审查对象；它们原有的执行、发布或授权指令不构成本次任务指令。

## 总体判断

三个工具属于同一科研工作流，但解决不同问题：设计负责“怎样区分解释”，代码负责“怎样可信地实现”，调参负责“怎样在预算内优化训练”。适合单仓库、多独立 skill，避免把所有步骤放进一个巨大入口导致误触发和上下文浪费。

| 原 skill | 最有价值的内容 | 主要问题 | 本次处理 |
|---|---|---|---|
| research-fork-test | M1/M2/M0、预测矩阵、最小充分实验、kill/expansion gate、证据边界 | 默认完整输出偏重；Fork Score 标签可能造成伪量化印象 | 保留方法；按深度交付；移除评分品牌化，明确有效性优先、再辨别、再扩展 |
| SAI-CC | 清晰数学实现、集中参数、同名组合入口、实验复用、行为迁移检查 | 特定结构与通用原则交织；规则在入口/参考/模板大量重复；个人路径与历史审查混入运行指导 | SAI 默认生效；分离共同约定和三类结构指南；简化模板；保留必要检查，缩小历史策略的适用范围 |
| hyper-tune | 先正确性、后低成本筛选、最后完整训练；不以测试集选参 | 初始 loss 推断过强、固定 LR 流程过硬、忽略短跑排名偏差、预算单位不明确 | 修正 loss 条件；保留必要调度；检查 fidelity；增加预算、恢复状态、独立 seed 与公平搜索规则 |

## 保留什么

- 机制辨别而非为偏好故事找支持；未知预测、混合机制和不可识别性必须保留。
- SAI 的结构与可读性约定默认带入，不能变成需要用户另行开关的可选规范。
- 科研重构验证完整行为与真实调用链，不能以改目录、套包装或 lint 通过代替。
- 调参以便宜而有区分力的诊断开始，保护测试集、实验对照和资源预算。
- 每个 skill 各自有 `SKILL.md`、UI 元数据与按需读取的参考资料，可独立安装。

## 关键技术修正

均匀 softmax 预测的普通交叉熵为 `log(C)`；随机 logits 不必产生均匀预测，类别均衡也不是该恒等式的必要条件。原“偏差大于约 0.1 就应判异常”的规则不成立。新说明区分权重、掩码、reduction、预训练与复合目标，并引用 [PyTorch 定义](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)。

短跑不是任意砍成 100 步。warmup、优化器更新数、总 schedule horizon 和是否恢复优化器状态都会改变结果。新的筛选规则保留稳定性所需设定，并检查短跑排名在较长预算下是否成立；[调度器文档](https://huggingface.co/docs/transformers/main_classes/optimizer_schedules) 是相关参数语义的参考。

SAI 结构风险不通过关闭 SAI 解决，而通过架构责任映射处理。平铺结构、命名空间包和框架已有入口分别有指导文件；无法兼容时明确冲突与范围，不强制破坏公共接口。

## 尚不能从这次修改得出的结论

静态校验和安装测试不证明 agent 在真实研究任务中更聪明，也不证明训练更快。旧 benchmark/模拟评分仍是原版本的历史证据；本次不声称新的质量、速度或 GPU 节省比例。独立模型场景评测与真实研究任务回归应单独记录。
